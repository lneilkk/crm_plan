## 3. 화면별 기능

### 3-1. 로그인·계정

- 로그인은 비밀번호를 argon2로 저장합니다. 5회 틀리면 계정이 잠깁니다.
- 직원은 자기 비밀번호를 직접 바꿀 수 있습니다(F-1).
  - 규칙: 8자 이상에 문자 종류 3가지, 또는 10자 이상에 문자 종류 2가지.
  - 아이디가 들어간 비밀번호는 쓸 수 없습니다.
- 역할은 5가지입니다. 메뉴는 역할에 따라 보이지만, **실제 차단은 서버의 권한 검사**가 합니다.

| 할 수 있는 일 | 프론트 | 상담 | 원장 | 간호 | 관리자 |
| --- | :-: | :-: | :-: | :-: | :-: |
| 고객·예약 보기 | O | O | O | O | O |
| 고객 등록·수정, 예약 만들기·고치기 | O | O | – | – | O |
| 내원 상태 변경 | O | O | – | O | O |
| 상담 보기 | – | O | O | – | O |
| 상담 쓰기·수술예약 전환 | – | O | – | – | O |
| 수술 참여 직원 기록 | O | O | O | O | O |
| 수술 메모(실수 등) | – | – | O | – | O |
| 통계·실적 | – | – | O | – | O |
| 설정 편집·직원 관리·데이터 가져오기 | – | – | – | – | O |

### 3-2. 내원 보드 (오늘)

- 오늘 예약을 시간순으로 보여 줍니다. 상태(내원·완료·노쇼·취소 등)는 한 번 눌러 바꿉니다.
- 잘못 누른 상태는 5초 안에 되돌릴 수 있습니다. 노쇼에는 사유를 받습니다.
- 위쪽 요약에 내원·대기·노쇼·미확인 수가 나옵니다. 지각과 노쇼는 병원 설정의 허용시간·유예시간으로 판정합니다.
- 상태를 바꿀 때마다 변경 이력(visit_status_log)이 같은 트랜잭션으로 남고, 이력은 고칠 수 없습니다.
- 신환에는 배지가 붙습니다.

### 3-3. 예약 캘린더

- **보기와 열:**
  - 일 보기·주 보기가 있고, 체어별 열이 나옵니다.
  - 열은 과별로 묶을 수 있습니다. 예: 보철과·수술과(F-14).
  - 칸 크기(가로·세로)를 고를 수 있고, 브라우저마다 기억합니다(F-3).
  - 오늘 일 보기에는 **현재 시각 선**이 30초마다 움직입니다(F-13).
  - 상태는 자동으로 바뀌지 않고 직원이 직접 고릅니다.
- **예약 만들기·옮기기:**
  - 드래그로 예약을 옮길 수 있습니다.
  - 같은 체어에 시간이 겹치면 막습니다. 동시에 들어온 요청도 DB 제약으로 막습니다.
- **칸 색:**
  - 우선순위는 **색 라벨 > 진료 항목 색 > 예약 상태 색**입니다(F-2, F-9).
  - 왼쪽 띠는 항상 상태 색입니다.
  - 예약 하나에 라벨을 여러 개 붙일 수 있고, 칸 색은 대표 라벨 하나의 색을 씁니다.
- **예약 상세:**
  - 평소에는 보기 전용입니다. **[고치기]**를 눌러야 메모·항목·체어·담당 의사·상담자·할인율을 고칠 수 있습니다(F-8, F-12).
  - 상담실 열에는 임플란트·라미네이트 같은 **고가 항목만** 들어갑니다(F-5). 항목을 일반 진료로 바꾸면 진료 체어로 옮겨야 저장됩니다.
- **수술 기록:** 고가 항목 예약에는 참여 직원(간호·의사 등)과 수술 메모가 있습니다(F-11). 메모는 원장·관리자만 보고 쓰며, 볼 때마다 감사 로그에 남습니다.

### 3-4. 고객

- 등록·수정, 검색(전화번호 뒷 4자리, 이름, 차트번호)이 됩니다. 가짜 환자 500명 기준으로 검색 응답(p95)이 0.5초 안입니다.
- **같은 번호 경고:** 같은 번호의 다른 이름이 있으면 경고합니다. 가족이 번호를 같이 쓰는 경우를 위해 [그래도 등록]으로 저장할 수 있습니다.
- **신환·구환(F-4):**
  - 이름과 번호가 모두 같으면 새로 만들지 않고 기존 고객(구환)으로 안내합니다.
  - 한 번이라도 내원하면 자동으로 구환이 됩니다.
  - 목록에 [신환만] 필터가 있습니다.
- **저장 방식:**
  - 목록에서는 이름·번호를 가립니다(마스킹).
  - 전화번호와 생년월일은 DB에 암호문(AES-256-GCM)으로만 저장합니다.
  - 메모에 주민등록번호 형식이 있으면 저장을 거부합니다.

### 3-5. 상담 (F-10)

- 날짜별 상담 보드입니다. **신환상담·구환상담** 묶음 안에 상담자별 열이 있습니다.
- 결과 분류는 [편집]에서 이름·색·종류를 바꿉니다. 예: 예진완료·사진완료·수술예약·일반진료·실패·임플불가.
- 위쪽에 결과별 건수와 전환율을, 아래쪽에 상담자별 이번 달 표를 보여 줍니다.
- **[→ 수술예약]**으로 상담에서 바로 고가 항목 예약을 만듭니다. 이 예약은 상담과 연결되어 상담자 실적에 잡힙니다.
- 상담 내용은 민감정보입니다. 동의 기록이 없는 고객은 동의를 체크해야 저장됩니다(기획서 10장).

### 3-6. 통계·실적

- **통계:** 실내원율·노쇼율·당일취소율·지각률을 일·주·월로 봅니다. 예약이 없는 구간은 비워 둡니다.
- **실적(F-6):** 의사·상담자별, 항목별로 환자 수와 금액을 봅니다.
  - 금액은 예약 당시의 항목 단가에 할인율을 적용합니다.
  - 단가를 나중에 바꿔도 지난 실적은 바뀌지 않습니다.

### 3-7. [편집] — 관리자 설정 (F-2, F-14, T4-4, T2-5)

왼쪽 하위 메뉴 7개입니다.

| 메뉴 | 고칠 수 있는 것 |
| --- | --- |
| 예약 항목 | 항목 추가, 고가·일반 구분, 단가, 칸 색 |
| 색 라벨 | 라벨 이름·색·순서 |
| 상태 표시 | 상태별 표시 이름·색 (상태 종류는 기획서 4-1 그대로) |
| 체어·열 | 열 추가, 이름, 순서, 묶음(과) 이름. 예약이 남은 열은 지울 수 없음 |
| 상담 결과 | 결과 분류 이름·색·종류 |
| 진료시간·기준 | 요일별 진료시간, 지각 허용시간, 노쇼 유예시간 |

직원 메뉴의 보호 장치:
- 비활성화하거나 비밀번호를 초기화하면 그 직원의 로그인이 즉시 끊깁니다.
- 자기 계정과 마지막 관리자는 실수로 없앨 수 없게 막았습니다.

  - 비밀정보 스캔
- **시간 기준:** 날짜 경계·요일·당일 판정은 모두 한국 시간입니다. DB에는 UTC로 저장합니다.

## 6. 운영 환경 (시험 서버)

- **서버:** AWS 서울 EC2 한 대(arm64)에 앱·DB를 Docker Compose로 띄웠습니다.
- **HTTPS:** Caddy가 Route 53 DNS 인증으로 인증서를 받습니다.
- **접속:** 보안 그룹으로 병원·관리자 IP에서만 80·443을 엽니다. 서버 관리는 SSH 대신 AWS SSM으로 합니다.
- **배포:** 서버에서 git pull 후 다시 빌드합니다. DB 마이그레이션은 배포 때 자동으로 적용됩니다. 절차는 `docs/DEPLOY.md` 6장에 있습니다.
- **주의:** 서버에서 시드를 다시 돌리면 직원 비밀번호가 초기화됩니다. 계정은 [편집] → [직원]에서 관리하세요.

## 7. 기획서와 다른 점 (체크리스트 검증 메모에 기록)

- **프로토타입 서버:** 기획서는 R1~R2를 "AWS가 아닌 외부 서버"로 정했습니다. 사용자 결정으로 AWS EC2 한 대에 올렸습니다. R3 본 구성(Terraform, RDS 등)은 아닙니다.
- **자동 상태 변경:** 하지 않습니다(F-13 결정). 대신 현재 시각 선을 보여 줍니다.
- **새 테이블·칸:** 기획서 6장에 없는 것을 피드백 때문에 추가했습니다.
  - 색 라벨, 상태 표시 설정
  - 항목 단가·할인율
  - 상담 결과 분류
  - 수술 참여 직원·수술 메모
  - 간호 역할
- **고객 상세 화면:** 전체 번호·생년월일을 바로 보여 주고, 그 조회를 감사 로그에 남깁니다. 기획서의 [원문 보기] 방식은 T3-3(R3)에서 만듭니다.
- **상태 전환 세부 결정 (T5-1):**
  - 지각내원은 저장하지 않고 계산합니다.
  - 당일취소는 예약일이 지난 뒤에도 입력할 수 있습니다.
  - 예약변경은 되돌릴 수 없습니다(새 예약이 이어받음).
